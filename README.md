## Проблема
Пациенту нужно выбрать чекап из пакетов PRIME, но он не знает, какие обследования нужны ему с учётом возраста, пола и
анамнеза, и что часть обследований положена бесплатно по госскринингу. После чекапа результаты разрознены, повторы
пропускаются. Клиника не знает заранее, сколько чекапов пропустит за день и где будет очередь.

## Решение
Цепочка трека целиком: **анкета → программа PRIME → информированное согласие → подготовка → маршрут дня → врач-куратор →
карта здоровья → напоминание о повторе**, плюс **утро клиники** (карусель кабинетов) и **запись по дням**.

Без ИИ-моделей и внешних сервисов: все правила — таблица `spec/rules.json`, у каждой строки источник (приказ МЗ РК
ҚР ДСМ-174/2020 в ред. приказа № 75 от 10.07.2026, страницы пакетов primegc.kz, решения медэксперта). **Врач утверждает
правила один раз — скрипт применяет их к каждому пациенту. Диагноз не ставим.**

**Принцип (решение команды 30.09.2026): всё ясно и явно — действуем по нормативу; есть неясность — «уточнить у врача».**
Пропущенный или неявный ответ никогда не считается «нет».

| Шаг | Что происходит | Где в коде |
|---|---|---|
| 0. Согласие на обработку ответов | в первом шаге анкеты; имя и ИИН не спрашиваем | `anketa_fields.py` |
| 1. Анкета | форма Натальи, 6 шагов, простые слова; «беспокоит прямо сейчас» → стоп, 103 | `static/anketa/` |
| 2. Программа | пакет PRIME по полным годам и полу; госскрининг по году достижения возраста; «бесплатно в поликлинике до 60 дней — или в PRIME сегодня» (по умолчанию — бесплатно); добавки сверх пакета по анамнезу; онкомаркеры — по выбору куратора; «Нужно уточнить у врача» | `engine.py` |
| 3. Информированное согласие | по каждой процедуре: что, зачем, риски, альтернатива; письменно у куратора (Кодекс РК «О здоровье народа…», ст. 134) | `spec/rules.json → consent_catalog` |
| 4. Подготовка | по дням, под каждым пунктом вопрос на понимание, иллюстрации | `prep_catalog`, `static/img/prep/` |
| 5. Маршрут дня | по кабинетам медэксперта, у каждой процедуры «Как подготовиться» | `engine._route_rooms` |
| 6. Врач-куратор | видит анкету; выбирает состав; без подписи согласия утвердить нельзя; итоговый лист на печать | `static/app.js` |
| 7. Карта здоровья | отметки, результаты, оценка 1–5, повторы в календарь (.ics) | `static/app.js` |
| ★ Утро клиники | 13 кабинетов по списку медэксперта (УЗИ 3 места ⇄ 2, ФГДС и колоноскопия отдельно, колоноскопия последней, УЗИ 20 мин за исследование); каждому своё время прихода (не позже 10:30 — кровь натощак); сколько чекапов в день до 18:00 | `engine.morning`, `engine.capacity` |
| ▶ 25 пациентов | все этапы для 25 синтетических пациентов, запись по дням | `api_logic.api_scenario` |

Модель на демо-данных (не замер): утро 10 пациентов — среднее ожидание **133 → 14 мин** при своём времени прихода;
**10 полных чекапов в день** до 18:00 при 3 местах УЗИ (8 — при 2); 23 пациента раскладываются на 3 дня.

### Что протыкать (чек-лист, 5 минут)
1. http://localhost:8010 — анкета: согласие, пол, дата рождения… В «Самочувствие» выберите «Боль в груди» — анкета
   останавливается (103). Верните «Нет», дойдите до «Показать программу».
2. «Программа»: слева бесплатное (переключите «в поликлинике / в PRIME сегодня» — платная копия в пакете снимается сама),
   справа пакет с акцентами, онкомаркеры «по выбору куратора», блок «Нужно уточнить у врача» (если есть).
3. Ниже — «Информированное согласие» (отметьте «понятно») и маршрут дня с «Как подготовиться» и иллюстрациями.
4. «Подготовка» — ответьте на вопросы. «Куратор» — «Утвердить» неактивна, пока не отмечено «Бланки согласия подписаны»;
   отметьте онкомаркер, утвердите, «Итоговый лист (печать)».
5. «Карта здоровья» — отметки, оценка, «В календарь». «Утро клиники» — переключите УЗИ 3 ⇄ 2. «25 пациентов» — все этапы.
6. Кнопка «▶ Демо» в шапке — автопоказ.

## Запуск
Нужен Python 3.10+ (проверено на 3.12 и 3.13). Интернет нужен только для установки пакетов.

**Windows (PowerShell):**
```powershell
git clone -b final https://github.com/Natalia912/MedHub-HAQathon.git checkup-final
cd checkup-final
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\python.exe -m uvicorn app:app --port 8010
```
**macOS / Linux:**
```bash
git clone -b final https://github.com/Natalia912/MedHub-HAQathon.git checkup-final
cd checkup-final
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
pytest -q
uvicorn app:app --port 8010
```
Откройте http://localhost:8010 (анкета) и http://localhost:8010/app (остальные экраны). Если порт занят — `--port 8011`.

### Проверки
- `pytest -q` — **6 проверок**: 12 контрольных пациентов (`spec/examples.json`), эталонные анкеты формы и карусель,
  согласие и подготовка по кабинетам, исправления по сценариям, запись 25 пациентов по дням до 18:00,
  прогон сценариев.
- `python tools/run_ml_scenarios.py` — **46 состояний из 25 карточек `Scenarios.docx`** (ветка `ml`) через наш движок:
  пакет, 7 госскринингов, остановка. Результат: **46 из 46, 287 из 287 статусов, стоп 3 из 3**. Отчёт — `spec/scenarios_ml/REPORT.md`.

## Структура проекта
```
app.py              FastAPI: страницы (/ — анкета, /app — остальные экраны) и API
api_logic.py        утро клиники и сценарий 25 пациентов (без веб-сервера — это же исполняется в онлайн-копии)
engine.py           движок: predict() — программа, скрининги, «уточнить», согласие, подготовка, маршрут;
                    morning() / capacity() — карусель кабинетов и вместимость дня. Правил в коде нет — только порядок
anketa_fields.py    вопросы анкеты (форма Натальи) + согласие на обработку ответов
spec/rules.json     ВСЕ правила с источниками: пакеты PRIME, 7 госскринингов, анамнез, подготовка, согласия, кабинеты
spec/examples.json  12 контрольных пациентов с ожидаемым ответом
spec/demo_patients.json   25 демо-пациентов (24 карточки Scenarios.docx + пациентка «▶ Демо»)
spec/scenarios_ml/  Scenarios.docx, prime_scenarios.json (из ветки ml) и REPORT.md прогона
normativ/           тексты приказа ДСМ-174/2020 и изменений № 75
static/anketa/      анкета (стиль Green Clinic), автопоказ demo.js
static/             экраны программы (index.html, app.js, style.css), автопоказ tour.js, подсветка spotlight.js,
                    иллюстрации подготовки img/prep/*.svg, шрифт Geologica (OFL)
tools/run_ml_scenarios.py   прогон сценариев ветки ml
tools/build_static.py       сборка онлайн-копии (dist/, движок в браузере через Pyodide)
test_engine.py      проверки
pitch/              интерактивный питч (index.html: →/пробел — шаг, S — заметки докладчика, F — экран),
                    pitch_v2.pdf, тексты и речь (CONTENT.md, STORYBOARD_V2.md), сценарий демо (DEMO_SCRIPT.md)
```

## Что готово
- Вся цепочка трека работает end-to-end: анкета → программа → согласие → подготовка → маршрут → куратор → карта →
  напоминание; утро клиники и запись по дням; автопоказ.
- Проверено: 6 автотестов; 46/46 сценариев карточек `Scenarios.docx`; онлайн-копия с тем же движком.
- Только open source, без ИИ-API, без баз данных и внешних сервисов (требование Green Clinic).
- Решения медэксперта внесены: жалобы убраны, семья и лекарства добавлены, «онкоцитология или ВПЧ», ВПЧ-тест к ПАП-тесту,
  онкомаркеры по выбору куратора, кабинеты клиники; пять спорных случаев решены принципом «неясно — уточнить у врача».

## Ограничения (честно)
- Правила анамнеза, подготовка к УЗИ/КТ/маммографии/ЭКГ и тексты согласий — черновик, утверждает врач клиники.
- Бланк информированного согласия — клиники; мы даём пояснение простыми словами и отметку «подписано».
- Цены пакетов на сайте PRIME не опубликованы — в программе не показываем.
- Кабинеты — со слов медэксперта; места, длительности, приход до 10:30 и конец дня 18:00 — допущения. Клиника вносит свои
  в `spec/rules.json → carousel`, код не меняется. Все цифры утра — модель на синтетических пациентах, не замер.
- Интеграции с МИС нет: на пилоте итоговый лист печатает куратор. Данные — только синтетические.
