## Проблема

Пациенту сложно выбрать чекап с учётом возраста, пола и анамнеза и разобраться, какие обследования доступны бесплатно по госскринингу. После чекапа результаты разрознены, а повторные обследования пропускаются. Клинике нужно планировать загрузку кабинетов и сокращать очереди.

## Решение

Продукт сопровождает пациента по цепочке: **анкета → программа PRIME → информированное согласие → подготовка → маршрут дня → врач-куратор → карта здоровья → напоминание о повторе**.

Python-движок применяет правила из `spec/rules.json`: подбирает программу, выделяет госскрининги и дополнительные обследования, формирует подготовку и маршрут по кабинетам. Неясные или пропущенные ответы направляются на уточнение врачу. Интерфейс куратора позволяет согласовать состав программы и распечатать итоговый лист.

Для клиники предусмотрена модель загрузки кабинетов: расчёт времени прихода, ожидания и распределения пациентов по дням. Расчёты работают без ИИ-моделей и внешних API. Продукт не ставит диагнозы; медицинские правила требуют утверждения врачом клиники.

## Запуск

**Требования:** Python 3.10+, браузер и интернет для установки зависимостей. Команды выполняются из корня скачанного или клонированного репозитория.

**Windows (PowerShell):**

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn app:app --port 8010
```

**macOS / Linux:**

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m uvicorn app:app --port 8010
```

Откройте [анкету](http://localhost:8010) или [остальные экраны приложения](http://localhost:8010/app). Если порт занят, замените `--port 8010` на `--port 8011` и используйте этот же порт в адресе браузера. Для остановки сервера нажмите `Ctrl+C`.

**Переменные окружения:** не требуются. Файл `.env`, API-ключи и подключение к базе данных для локального запуска не нужны. Правила и параметры кабинетов задаются в `spec/rules.json`.

**Проверки (Windows):**

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe tools/run_ml_scenarios.py
```

Запускайте проверки после установки зависимостей, в отдельном терминале, если сервер уже работает. На macOS / Linux используйте `.venv/bin/python` вместо `.\.venv\Scripts\python.exe`. Прогон сценариев перезаписывает [spec/scenarios_ml/REPORT.md](spec/scenarios_ml/REPORT.md); он также вызывается одним из тестов `pytest`.

| Путь | Назначение |
| --- | --- |
| `app.py` | FastAPI-сервер: анкета `/`, экраны `/app` и API. |

| `normativ/` | Нормативные материалы, использованные при подготовке правил. |

| `pitch/` | Презентация, PDF, скриншоты и сценарий демонстрации. |

## Что готово

**Реализовано:**

- Анкета из шести шагов с согласием на обработку ответов и остановкой сценария при тревожных симптомах.
- Подбор пакета PRIME, семи госскринингов и дополнительных обследований по правилам; блок вопросов для уточнения у врача.
- Пояснения к информированному согласию, подготовка по дням с вопросами на понимание и маршрут по кабинетам.
- Экран куратора: выбор состава программы, проверка отметки о подписании согласия и печать итогового листа.
- Карта здоровья с отметками, результатами, оценкой и экспортом повторных обследований в календарь (`.ics`).
- Моделирование загрузки кабинетов, времени прихода и записи по дням; автопоказ и 25 демонстрационных пациентов.
- Шесть автотестов и прогон 46 состояний из 25 сценарных карточек. В сохранённом отчёте: 46/46 состояний, 287/287 статусов скрининга и 3/3 остановки сценария.

**Известные ограничения:**

- Правила анамнеза, часть инструкций по подготовке и тексты согласий остаются черновиками до утверждения врачом клиники.
- Приложение показывает пояснения и отметку о подписании согласия; официальный бланк предоставляет клиника.
- Цены пакетов в программе не отображаются.
- Загрузка кабинетов и время ожидания рассчитаны на синтетических пациентах. Длительности, число мест и границы рабочего дня — допущения модели, которые клиника должна уточнить в `spec/rules.json`.
- Интеграции с медицинской информационной системой и базы данных нет. Итоговый лист печатает куратор; демонстрация использует синтетические данные.
